# Тикет #7 — Төлбөрийн бүтцийн график

## Зорилго

Харилцагч үр дүнгийн доор сар бүрийн төлбөр үндсэн зээл ба хүү хоёрт хэрхэн
хуваагдахыг нэг харцаар харна. Нийт төлөх дүнгийн хэдэн хувь нь хүү болохыг
тоогоор уншиж, эргэн төлөлтийн хоёр аргын ялгааг график дүрсээр ялгана.

## Хамрах хүрээ

- `src/lib/loan.ts` — шинэ экспорт (хувь тооцох бүх логик энд, UI-д биш):
  - `PaymentBreakdown = { months: { month, principal, interest }[]; totalPrincipal;
    totalInterest; totalPayment; principalShare; interestShare }`,
    `principalShare`/`interestShare` нь 0..100 хоорондох хувь, дугуйлаагүй;
  - `paymentBreakdown(amount, monthlyRatePercent, termMonths, type: RepaymentType = 'annuity'): PaymentBreakdown`.
    `buildSchedule`-ийн мөрүүдээс байгуулна — ингэснээр график, хүснэгт хоёрын
    тоо хэзээ ч зөрөхгүй. `totalPayment = 0` үед хоёр хувь хоёулаа `0`.
- `src/lib/loan.test.ts` — шинэ `describe('paymentBreakdown')`: хувийн жишээ,
  `principalShare + interestShare === 100`, `months.length === termMonths`,
  хоёр аргын хүүгийн хувь (үндсэн төлбөр тэнцүү нь аннуитетээс бага).
- Шинэ бүрэлдэхүүн `src/lib/components/BreakdownChart.svelte` — цорын ганц проп
  `breakdown: PaymentBreakdown`. Дотроо SVG-ээр давхарласан баганат график зурна,
  доор нь хоёр өнгөний тайлбар (legend) — `formatTugrik`-аар ₮ дүн, нэг аравтын
  орноор хувь.
- `src/lib/components/LoanCalculator.svelte` — `let breakdown = $derived(...)`
  (оролт зөв үед `paymentBreakdown(amount, rate, term, repaymentType)`, эс бөгөөс
  `null`), `</main>`-ийн дараа, хуваарийн картын өмнө `.schedule-card`-тай ижил
  хэв маягийн шинэ `<section>` — `<h2>Төлбөрийн бүтэц</h2>` + `<BreakdownChart>`.
- Шаардлагатай бол `src/app.css`-д графикийн токен — зөвхөн дизайны алхмаас
  гарсан `docs/design/ui.txt`-ийн утгаар.

## Хамрахгүй

- Шинэ npm хамаарал, график сан (Chart.js, d3, LayerCake гэх мэт). SVG гараар.
- `calculateLoan`, `buildSchedule`, `interestSavings`-ийн томьёо, дугуйлалтын
  дүрэм, одоогийн тестүүдийн утга.
- `ResultPanel.svelte`, `ScheduleTable.svelte`, `RepaymentTypeField.svelte`,
  гурван оролтын талбар, валидаци, caret-ийн логик.
- Хуваарь татаж авах, хэвлэх, зээлийн хүсэлт илгээх.
- Hover/tooltip, анимаци, тэнхлэгийн шошго бүрэн, zoom, графикийг зураг болгох.
- Хоёр аргыг зэрэгцүүлэн нэг график дээр харьцуулах.

## Нээлттэй асуултыг шийдсэн таамаглалууд

- **"Үр дүнгийн доор" гэдэг хаана вэ.** Desktop дээр `ResultPanel` нь баруун
  баганад байдаг тул "доор" нь `.main`-ий **дараах** бүтэн өргөнтэй шинэ карт
  гэж тайлав: маягт+үр дүн → **Төлбөрийн бүтэц** → Эргэн төлөлтийн хуваарь.
  Mobile дээр ч энэ дараалал үр дүнгийн шууд доор буухад таарна.
- **Хувь ямар хуваариас гарах вэ.** Хуваарь нь `totalPayment` (үндсэн зээл +
  нийт хүү), өөрөөр хэлбэл `interestShare = totalInterest / totalPayment · 100`.
  10,000,000₮ / 2% / 12 сар / аннуитет дээр ≈ 11.87 → харуулахдаа `11.9%`.
- **Тоо хаанаас гарах вэ.** `paymentBreakdown` нь `buildSchedule`-ийн дугуйлсан
  мөрүүдийг нийлбэрлэнэ, `calculateLoan`-ы дугуйлаагүй дүнг биш. Хэдэн төгрөгийн
  зөрүү гарч болох ч хэрэглэгч графикийг доорх хүснэгттэй тулгах үед таарна.
  Хувь нь энэ сонголтоос нэг аравтын орны хэмжээнд хамаарахгүй.
- **Хувийг дугуйлах.** Логик нь дугуйлаагүй `number` буцаана; `toFixed(1)`
  форматлалт нь `BreakdownChart.svelte` дотор. Хоёр хувь нийлээд `100.0` болохгүй
  тохиолдол гарвал (жишээ нь `49.95`/`50.05`) зөвхөн харагдац зөрөх ба үүнийг
  зассан залруулга **хийхгүй** — тестэд дугуйлаагүй нийлбэрийг шалгана.
- **120 багана нарийн дэлгэцэд.** SVG нь `viewBox="0 0 n·unit H"`,
  `preserveAspectRatio="none"`, CSS-ээр `width: 100%` ба тогтмол өндөртэй —
  багана бүрийн өргөн сараас хамаарч автоматаар сунана/нарийсна. Иймээс
  `stroke` ашиглахгүй (x тэнхлэгт сунахад зузаан нь гажина), зөвхөн `fill`.
  Багана хоорондын зай нь багананы өргөний хувиар (жишээ нь 20%) тогтоогдоно —
  120 сарын үед хэдхэн зуун пикселийн ялгаа харагдахаа болих нь хүлээн
  зөвшөөрөгдсөн, гол нь гүйлгэлтгүй багтах.
- **Багананы өндрийн масштаб.** Бүх багананы өндөр хамгийн их сарын төлбөрөөр
  (`Math.max`) хуваагдаж тооцогдоно. Аннуитет үед бүх багана бараг тэнцүү, зөвхөн
  доторх өнгөний харьцаа өөрчлөгдөнө; үндсэн төлбөр тэнцүү үед багана зүүнээс
  баруун тийш буурна — энэ ялгаа нь хоёр аргыг нэг харцаар ялгах гол дохио.
- **Өнгө.** `docs/design/ui.txt`-д график одоогоор алга. Үндсэн төлбөр нь
  `var(--accent)`, хүү нь `var(--accent-bright)` гэж түр авав — эцсийн өнгө,
  өндөр, тайлбарын байрлалыг дизайны алхам шийдэх ба шинэ токен зөвхөн
  `ui.txt`-ээс `app.css`-д орно.
- **Хүртээмж.** SVG нь `role="img"` ба нийт бүтцийг нэг өгүүлбэрээр хураангуйлсан
  `aria-label` авна (жишээ нь "12 сарын төлбөрийн бүтэц: хүү 11.9%"). Багана
  тус бүрийг дэлгэц уншигчид уншуулахгүй — тэр мэдээлэл хуваарийн хүснэгтэд
  аль хэдийн хүснэгт хэлбэрээр байгаа. `aria-live` ашиглахгүй.
- **Хүү 0 үед.** `totalInterest = 0`, хүүгийн давхарга өндөргүй, тайлбарт `0₮`
  ба `0.0%` харагдана — алдаа биш, тусгай текст нэмэхгүй.

```factory
has_ui: true
rationale: Хуудсан дээр урьд байгаагүй график болон түүний тайлбар хэрэглэгчийн нүдэнд шинээр нэмэгдэж, эргэн төлөлтийн төрөл солихоос хамаарч дүрс нь өөрчлөгдөнө.
```

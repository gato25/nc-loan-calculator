# Тикет #7 — test

## Зорилго

Тикетийн гарчиг "test", тайлбар "test", хүлээн авах шалгуур хоосон. Өөрөөр хэлбэл
бүтээгдэхүүний ямар ч шаардлага агуулаагүй, дамжуулах шугамыг шалгах туршилтын
тикет. Зорилго нь репозиторийн өөрийн шалгах скриптүүд одоогийн `main`-аас салаалсан
кодон дээр алдаагүй гүйхийг батлах — бүтээгдэхүүнд шинэ зан төлөв нэмэхгүй.

## Хамрах хүрээ

- `npm run typecheck`, `npm test`, `npm run build` гурвыг гүйцэтгэж, гаралтыг
  тайлбарлах.
- Дээрх гурваас алдаа гарвал зөвхөн тэр алдааг шууд арилгах хэмжээний засвар
  (жишээ нь `src/lib/loan.test.ts`-ийн эвдэрсэн assertion, `svelte-check`-ийн
  төрлийн алдаа).
- Хэрэв гурвуул ногоон бол кодод өөрчлөлт гаргахгүй. Энэ тохиолдолд `src/`-д
  нэг ч файл өөрчлөгдөхгүй байх нь зөв хүлээгдэх үр дүн.

## Хамрахгүй

- `src/` доорх ямар нэг шинэ функц, бүрэлдэхүүн, тест нэмэх.
- `src/lib/loan.ts`-ийн томьёо, `formatTugrik`, `LoanCalculator`, `ResultPanel`,
  `ScheduleTable`, `RepaymentTypeField`-ийн зан төлөв, харагдац.
- `src/app.css`, `docs/design/` доорх дизайны токен, экспорт.
- `package.json`-ы script, хамаарлын хувилбар шинэчлэх, шинэ сангийн суулгац.
- Тестийн хүрээ (coverage) өсгөх, шинэ тестийн дүрэм тогтоох, CI тохируулах.
- Тикетийн агуулгыг таамаглаж "test" гэдгийг ямар нэг онцлогийн шаардлага болгон
  тайлах.

## Хүлээн авах шалгуур (дахин найруулсан)

Тикет шалгуур өгөөгүй тул дараах гурвыг тогтоов:

| # | Шалгуур |
|---|---------|
| 1 | `npm run typecheck` алдаагүй дуусна. |
| 2 | `npm test` бүх тест ногоон, унасан тест байхгүй. |
| 3 | `npm run build` алдаагүй дуусна. |

Гурвуул ногоон бөгөөд `git status` цэвэр (`src/` өөрчлөгдөөгүй) байвал тикет
хүлээн авагдсанд тооцно.

## Нээлттэй асуултыг шийдсэн таамаглалууд

- **"test" ямар нэг онцлог гэсэн үг үү?** Үгүй. Гарчиг, тайлбар хоёулаа "test",
  шалгуур хоосон, дизайны экран хоосон тул бүтээгдэхүүний шаардлага болгон
  тайлбарлахгүй. Таамаглаж онцлог нэмэхээс татгалзаж, шалгалт гүйцэтгэх тикет
  гэж авав — буруу таамаглалаар код нэмэхээс хоосон дүн гаргах нь илүү аюулгүй.
- **Шинэ тест бичих үү?** Үгүй. "test" гэдэг нь шинэ тестийн хүсэлт гэх
  баталгаа байхгүй; аль файлд, ямар зан төлөвт тест нэмэхийг тикет заагаагүй.
- **Гүйлт унавал?** Тикетийн хүрээг өргөсгөхгүй, зөвхөн тухайн алдааг арилгах
  хамгийн бага засвар хийж, ямар алдаа байсныг тайлбарлана. Рефактор хийхгүй.
- **Хоосон дүн хүлээн зөвшөөрөгдөх үү?** Тийм. Кодын өөрчлөлтгүйгээр гурван
  шалгалт ногоон болсон тайлан нь бүрэн гүйцэд хүргэлт гэж тооцно.

```factory
has_ui: false
rationale: Тикет бүтээгдэхүүний ямар ч шаардлага агуулаагүй бөгөөд хүрээ нь зөвхөн typecheck, тест, build гүйцэтгэхэд хязгаарлагдсан тул хэрэглэгчийн харах зүйл өөрчлөгдөхгүй.
```
